## DESIGN.md の読み方 — 追補方式で育てている

既存本文を書き換えず、章を足して更新してきた。**後の章が前の章を上書きする。**

| 章 | 版 | 内容 |
| --- | --- | --- |
| §01〜§13 | v1.0 | ブランドの土台（配色・タイポ・部品・ロゴ・ナビ・お問合せ） |
| §14 | v1.1 | アクセシビリティ補正。WCAG AA 実測に基づく配色の差し替え（**CTA 地は `#2276BE`**、リンクは Navy 600、`--danger` は `#C24444`） |
| §15 | v1.2 | ヒーローの明朝、写真上の白ハロ、画像比率、トークンの名前空間 |
| §16 | v1.3 | 写真ヒーロー・モーション・レイアウト確定値・電話番号の扱い |

§03 タイポグラフィのみ v1.3 で本文を書き換えている（フォント規則が二重管理になるのを避けるため）。

## 実装するときに必ず読む2点

1. **トークン名は独立した名前空間で宣言する。** 本書の `--blue-*` はユーティリティ CSS 標準のパレットと衝突するため、Web 実装では `accent-600`〜`accent-100` のように別名にする（§15-4）
2. **`--color-blue-*` を上書きしない。** CMS に保存済みのリッチテキストが `text-blue-800` のような標準クラスを直接含むことがあり、上書きすると既存記事の見た目が黙って変わる

配色は **§14 の補正値が現行**。v1.0 の §02 の表だけを見て CTA に `#2F8BD2` を使うと AA（4.5:1）を満たさない。

## 更新の運用

**規定を変えたら、同じコミットで `styleguide.html` も更新する。** 見本帳が古いままだと、色を写す人が補正前の値を実装に入れてしまう。詳細な手順は [AGENTS.md](./AGENTS.md)。
